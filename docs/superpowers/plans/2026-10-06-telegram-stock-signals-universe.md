# Telegram 股票信号扫描实施计划

## 目标

实现已批准设计：股票 `/signals` 扫描固定热门池、Nasdaq 美股异动池和当前聊天可访问的股票自选；按证券身份合并来源、每个候选均显示状态、每页最多 8 项，并保持其它市场行为不变。

## 执行边界

- 仅使用已有 Nasdaq 公共筛选器、股票 Provider、腾讯行情/K线适配器和既有技术评分。
- Nasdaq 异动只属于美股；A 股/港股没有来源时不伪造异动池。
- 网页管理员自选仅对 Telegram 管理员聊天可见；普通聊天只读自己的 Telegram 自选。
- 不接入订单、不改变信号阈值、不扫描/暴露 AI 跑单数据。
- 不触碰 `data/research.db*`、`scratch/`、生产配置和密钥。
- 每个任务按“测试先红 → 最小实现 → 定向测试绿”执行；任务间保留独立可检查提交。

## 任务清单

### 1. 股票身份、候选池合并与去重（已完成）

新增 `src/features/telegram-stock-signal-universe.ts`，统一解析既有股票 ID（如 `usAAPL`、`stock:us:AAPL`、`hk00700`、`stock:hk:00700`、`sh600519`、`stock:sh:600519`、`stock:sz:000001`），拒绝未知/跨市场 ID；固定热门列表保持当前 11 个核心标的。将 Nasdaq gainers/losers 显式归为 US movers；合并候选时按规范市场与证券身份去重，并保留 `fixed/mover/watchlist` 全部标签、异动涨跌幅和来源时间。

先在 `tests/telegram-stock-signal-universe.test.cjs` 增加失败测试：

- 多来源同股仅一条且标签完整；不同市场证券不能因裸代码相同而合并。
- Nasdaq mover 仅生成 US 身份；非股票 ID、错误市场身份不会进入池。
- 普通聊天只合入本聊天股票自选；管理员可以合入网页管理员股票自选。
- 固定池、异动源失败时仍保留固定池与可访问自选，并保留失败/空/过期来源状态。

**完成条件：** 定向测试通过；固定池名单和来源权限有显式断言。

### 2. 动态股票数据与逐标的结果（已完成）

在 `src/features/stock-data-service.ts` 增加不访问 SEC/基本面的缓存历史读取方法，返回 quote/history 的来源快照与失败原因；在 `src/features/trade-assistant.ts` 抽出可复用的单标的技术分析，使动态美股使用 Nasdaq quote/history、明确交易所身份的 A/H 股使用现有腾讯适配器，不再对未知美股代码猜 `.OQ`。保留既有评分阈值。新增扫描结果模型，候选即使数据失败/未轮到/历史不足也产出 `unavailable/pending` 状态，不把故障折叠成无信号。

先增加失败测试：

- 股票 `StockDataService.history()` 只调用 quote/bars，不调用 SEC filings/company facts；同标的在 TTL 内复用结果。
- 可用有效日线生成原有 BUY/SELL/WAIT 评分；行情或历史不可用、过期、数据不足时不给方向信号，并带 provider、数据时间和原因。
- 动态美股不拼接猜测交易所后缀；证券市场身份决定 provider。
- 限定并发与扫描预算后，未处理候选保留 `pending`，不会被静默丢弃。

**完成条件：** 新数据服务及技术分析定向测试通过；现有助手报告股票分析回归测试保持通过。

### 3. Telegram 每聊天扫描快照与分页（已完成）

新增 `src/features/telegram-stock-signals.ts` 与 `src/features/telegram-stock-signal-command.ts`：按 chatId 隔离短时扫描快照，逐项呈现 READY/WAIT/不可用/待扫描；每页 8 项，固定池、异动池和该聊天可见自选合并去重。单轮分析最多 32 个候选、并发最多 4；超出预算仍显示待扫描，可用 `/signals continue` 恢复，翻页不重复请求；完成后按来源池与 BUY/SELL/WAIT 排序。异动源有新鲜度标签，失败时仅沿用 24 小时内已保存的异动结果并明确标记过期。只存当前聊天可见候选，不把管理员网页自选快照共享给其它聊天。

先增加失败测试：

- 每页最多 8 个、页码边界清晰、所有候选可遍历，自选 WAIT/失败候选仍可见。
- 快照按聊天隔离并过期；页码参数非法时回到第一页。
- 展示 BUY/SELL/WAIT/数据不可用/等待扫描、来源标签、数据源和时间；来源失败与成功但零异动能区分。
- 股票 `/signals` 包含固定池、movers 和可见自选；非股票 `/signals` 保留现有语义。

**完成条件：** handler、分页、续批与恢复测试通过；所有扫描快照限定当前 chatId。已完成。

### 4. 主动信号提醒作用域与去重（已完成）

修正 `monitorTelegramSlowAlerts()` 的信号路径：股票聊天只读取本聊天扫描快照中的 READY BUY/SELL 股票信号，不把 overview 中的非股票或其他聊天的私有自选混入提醒。以每聊天最新扫描 ID 持久去重，SQLite lease 防止并发重复投递；发送失败不记成功，后续监控可重试；尊重信号通知偏好、静默/暂停策略，并在发送前再次校验聊天市场与最新快照。其他市场继续使用各自 scope 的助手信号，不改动行情/风险/事件提醒。

先增加失败测试：

- 普通聊天不会收到网页管理员自选对应的信号；管理员聊天按权限可见。
- 同一聊天同一股票/方向/版本只推一次；信号版本变化可再次发送。
- 股票当前市场不推送虚拟币/期权/预测市场信号；其他市场提醒继续可用。
- 关闭信号通知或暂停时不投递，但价格/风险类提醒保持既有路径。

**完成条件：** 通知作用域、有效候选过滤、持久去重和 lease 行为测试通过，未增加下单调用。已完成。

## 依赖与审查结论

- 顺序是身份池 → 数据/分析 → Telegram 快照分页 → 主动提醒 → 全量验收，满足依赖关系。
- 扫描通过既有依赖注入适配器及缓存实现，不需要新包或 API 密钥。
- 扫描候选数量必须有硬上限/有界并发；超出本轮预算的证券明确为待扫描并可通过分页后续扫描，不隐藏自选项。
- 任何跨市场身份无法唯一确认时拒绝猜测；仅凭裸代码不得解析成其他市场。
