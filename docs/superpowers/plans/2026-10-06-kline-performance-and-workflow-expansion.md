## 全局边界

- 全程不使用子agent；保持当前驾驶舱入口、三栏职责与三个主题。
- 当前功能区仅显示当前功能。大盘、今日待处理、私人摘要不混入13F、合约或其他专属工作区。
- 股票、期权、虚拟币、预测市场的身份、数据源、事件、订单与记录严格隔离；无法唯一确定身份时不猜测。
- 免费现有来源优先，付费或密钥源仅为可选增强。不复制第三方业务代码；TradingView适配器默认关闭。
- 模拟账本是唯一交易事实源，按账户和跑单隔离；不连接券商、不启用实盘下单。
- AI仅能提交经服务端重新校验的纸面意图或生成研究建议。模型不能修改预算、风控或标的范围。新增AI能力标志默认关闭，不因发布自动启动跑单或模型调用。
- 访客只读公开摘要；自选、任务、日记、组合、跑单和订单详情保持私有。
- 保留现有数据库、数据湖、缓存、用户脚本和`scratch/`，不纳入代码提交。

## 批次1：K线恢复与上下文修复

目标：普通行情、历史时点、日内下钻都能返回当前证券的数据或明确原因，不再出现静默空白。

1. 通过现有标的身份契约统一`usAAPL`、`AAPL`、已核验Provider代码与历史分区身份；保留已知旧编码兼容，不扩大为无规则字符串猜测。
2. 切换股票时仅恢复该股票保存的周期、时点和Provider配置；未保存的历史时点与旧Provider代码清空。
3. 保留请求版本校验，取消失效请求；晚到响应不能覆盖新的标的、周期或时点。
4. 图表区分别显示加载、成功、快照缺失、来源失败。无数据时收起空白画布，显示原因、重试及“退出时点”；禁用依赖数据的Replay与指标操作。
5. 无K线不再显示“未触发策略信号”；覆盖徽章以当前图表请求为准，不能用普通行情的覆盖情况冒充历史时点可用。
6. 历史时点只能读取当时已发布的分区；缺失时不回退到事后行情。日内下钻保留交易所时区和返回定位。

验收：身份别名、切股清理、晚到响应、退出时点、无数据状态、防未来分区测试；Chromium抽检AAPL和SNDK普通日K、历史时点、日内、Replay与全屏。

## 批次2：网页加载与交互提速

目标：减少首屏下载和无关请求，改善冷/热加载及市场、功能切换等待。

1. 拆出大型内联脚本；研究、13F、AI跑单、合约等工作区按需加载，保持DOM、事件处理和深链兼容。
2. 首屏只请求当前工作区和右侧库；移除选择股票时对隐藏功能的全量加载。复用现有缓存和请求合并，不建立平行数据服务。
3. 市场或标的切换取消旧请求；隐藏工作区停止前端轮询。来源独立超时、分别返回状态，单源失败不清空其他成功数据。
4. 构建生成带内容Hash的静态资源、压缩版本和缓存策略；私人API仍`no-store`。公开离线缓存不得包含私人内容。
5. 长列表分页或虚拟化，复用图表实例；优化时保留三个主题与窄屏布局。

验收：同环境桌面/手机冷、热加载和切换各测三次，记录请求数、传输字节、可操作时间。首屏可操作时间中位数目标改善至少30%；热加载命中版本化资源缓存；首屏不请求无关工作区。未达目标时如实记录瓶颈，不以体积下降替代交互速度证据。

## 批次3：自动股票扫描与信号前向跟踪

对应此前第1、2项扩充，复用现有扫描池、信号生命周期、偏差检测和质量中心。

1. 为固定池 + 异动池 + 可访问自选增加可配置定时扫描，识别交易所时区及交易时段；遵守Provider预算、并发上限、SQLite租约、去重和通知偏好。
2. 扫描结果显示池来源、进度、未扫描项、WAIT和来源不可用；来源失败不能伪装成无信号。
3. 为信号保存生成、确认、跟踪、失效和退出的时间、原因及证据；旧记录无明确关联时标记“未关联”。
4. 用触发后已完成的数据计算前向收益、MFE、MAE与确认延迟，按市场、策略版本、周期及来源分组，区分样本内、样本外和实时跟踪。
5. 保留低样本量、缺口、未来数据和多重检验警告；偏差治理仅暂停对应策略的信号提醒，人工恢复，不影响价格/风险提醒或模拟持仓。

验收：交易时段调度、聊天权限、多实例单持有者、去重、过期数据、前向时间边界和暂停/恢复审计。

## 批次4：Telegram操作与结果通知闭环

对应此前第3项扩充，复用网页状态、回调契约及outbox，不另建业务状态。

1. 股票信号增加池、方向、数据状态筛选和分页/继续扫描/刷新按钮；明确展示进度、来源、时间与每项不可用原因。
2. 监控不止发送倒计时：事件发生后读取官方实际值、预期值、前值和修订值；没有可靠结果源时显示“结果待发布/来源不可用”，不能臆测结论。
3. 通知记录倒计时、发生、结果、修订、ACK和发送状态，支持冷却、静默、全局/市场暂停、失败重试和最终失败可见性。
4. 查询、事件、信号、图表、证据、研究和复盘共享上下文；普通文本信息直接在聊天显示，复杂图表/研究通过安全公网深链打开。
5. polling lease、优雅停止、409退避和一次性回调继续有效；未经二次确认不得创建模拟订单。

验收：无可靠结果时不发伪结果；结果和修订去重；正文/按钮权限、深链、ACK、重试、暂停及轮询重载测试。真实Telegram投递证据与本地自动化结果分别报告。

## 批次5：规则与AI模拟策略对照

对应此前第4项扩充，建立在已批准AI模拟跑单深化方案及统一账本之上。

1. 相同冻结标的集、数据快照、起止时间、随机种子、预算和成本模型下比较`rules`、`ai-review`和`ai-autonomous-paper`。
2. 每轮记录下单、拒绝或无动作的原因、模型/策略版本、证据、风险门控、成本及独立账户血缘。
3. 展示权益、回撤、已实现/未实现盈亏、费用、持仓时间和持有基准；不以低样本胜率排名，不承诺盈利。
4. 过期报价、模型越权、错误格式、超时或调用预算耗尽均fail-closed；不静默切换算法，不保存模型私有思维链。

验收：同快照重放、账户隔离、幂等与租约、风险限制、模型限额、三主题与访客权限。默认关闭功能标志，不自动产生收费模型调用。

## 批次6：合约与衍生品研究深化

对应此前第5项扩充，优先扩展当前真实来源已有能力。

1. 比较同一底层、可核验合约身份和交易场所的报价、资金费率、基差及期限结构，明确现货/永续/交割和计价、结算、乘数口径。
2. 利用真实深度和报价进行容量、点差及滑点研究；无深度、保证金规则或风险参数时明确不可用，不生成假爆仓价或假成交。
3. 资金费率成本、保证金压力、杠杆风险与流动性缺口作为研究/模拟结果；不是实盘开仓建议。
4. 期权先做真实链快照、Greeks、Payoff和有限损失情景；历史不足不伪回测，多场所不可比时分别呈现证据。

验收：合约/单位/场所隔离、同合约比较、费用与乘数、缺失规则fail-closed、真实来源曲线和明确空状态。

## 批次7：组合分析与归因

对应此前第6项扩充，沿用统一账本、真实历史和现有导入模型。

1. 从账本、持仓批次、费用、股息、现金流及可用历史构建资金曲线；人工导入与模拟账户分别列示，明确选择后才合并。
2. 保留币种及有效汇率、交易所时区和日期对齐；缺少汇率、基准或历史时标明原因，禁止零收益兜底。
3. 提供集中度、行业/市场/策略暴露、相关性、风险贡献、回撤恢复与情景归因；不可计算项目不展示伪数值。
4. 仅生成再平衡预览和研究草稿，不创建订单、不改变策略状态。

验收：现金流、费用、币种、日期对齐、基准缺失、账户隔离、导入重复与私有权限。

## 批次8：界面、移动与通知体验收敛

对应此前第7项扩充，样式修复贯穿每一批，最终全页面复验。
