# MoneyMoney 日常运行深度增强

**目标：** 完成获批的十项增强，复用现有状态、证据和工作区；不改变跑单配置，不使用子 agent，不启用真实交易。

**执行：** 使用 executing-plans 和 test-driven-development；每批先运行失败测试，再实现，浏览器验收后才发布。禁止将本计划的未完成项报告为已上线。

## 批次与文件边界

- [ ] 交易时段：扩展 `stock-signal-schedule.ts`，检验节假日、早收市和源状态；不将普通周历推断当作官方休市证据。
- [ ] 自选变化地图：复用行动中心及自选身份，在对应工作区增加排序、变化和图表导航，不污染其他区。
- [ ] 策略点位演变：复用完整数据计算与稳定 ID，记录形成、撤销、确认及其原因，缩放不改变信号历史。
- [ ] 成交质量：扩展 `runner-execution-evidence.ts` 与当前成交证据抽屉，展示可核验的价格、延迟及成本；缺字段返回未知。
- [ ] AI 无动作统计：扩展 `ai-runner-diagnostics.ts`、现有 diagnostics 接口及 `dashboard-runtime.js`；按结构化门控分类，保留未知类别、区间和样本截断说明。
- [ ] 四市场风险日历：复用各市场事件及已核验时间，不将未知时刻填成午夜或复用股票事件。
- [ ] 退出压力测试：复用报价/深度与持仓身份；深度不足不外推，不创建订单。
- [ ] 研究失效跟踪：复用研究版本、修订和漂移证据；只提出复核，不自动更改策略。
- [ ] Telegram 排障：复用 outbox、结果历史及静默策略；解释实际投递记录，不编造未记录的抑制原因。
- [ ] 容量与性能预算：扩展现有诊断和数据湖配额，在空间不足时阻止非必要采集，保留业务状态。

## 每批验证

针对实际行为编写 `node --test tests/<module>.test.cjs`，先确认新断言失败；实现后复跑并运行 `npm run build`。源文件冻结后执行完整 `npm test`、Web/认证/浏览器/实时 K 线/合约冒烟、性能测量、安全扫描及 `git diff --check`。浏览器分别检查三个主题、桌面与手机以及访客权限。
