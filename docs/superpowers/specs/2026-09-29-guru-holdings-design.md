# “大神持仓”双视角功能设计

**日期：** 2026-09-29
**状态：** 用户已确认双视角方案；等待书面规格审查
**范围：** MoneyMoney 股票工作区的公开机构持仓查询

## 1. 目标与边界

新增“大神持仓”工作区，用两个互相关联的视角查询公开申报的股票持仓：

1. **按投资人/申报机构查看持仓**：查看某个公开申报主体的股票列表和相邻报告期变化。
2. **按热门股票查看持有人**：从当前股票热榜、自选或搜索结果进入，查看已跟踪申报主体对该股票的披露记录；保留现有按股票查询机构持有人概览的能力。

新增内容仅覆盖股票市场，只读研究，不创建订单、不接入券商，也不把公开申报描述成实时仓位。现有“机构持仓雷达”仍可作为按股票查看机构持有人的补充视图，其来源和状态与 SEC 数据分开呈现，不把不同来源的行合并或求平均。

## 2. 数据含义与展示规则

### 2.1 来源和时点

- SEC EDGAR 的 Form 13F 是首版投资人持仓的权威来源。每条记录保存申报主体、CIK、accession、表单类型、报告期、申报时间、修订状态和原始 SEC 链接。
- 页面分别显示“报告期截至”和“申报时间”，并显示该报告距今的天数。13F 为季度披露，通常在季度结束后 45 天内提交；界面明确标注“延迟披露，不代表实时持仓”。
- 13F 报告不包含空头仓位。UI 和导出不得称其为完整账户资产或净仓位。
- 若 SEC 来源不可用，可展示已有缓存，但必须标记缓存/历史状态、原报告期和最近抓取时间；无缓存时显示真实失败原因，不补造数据。

### 2.2 持仓变化的准确措辞

同一申报主体按相邻两个有效报告期比较。使用报告披露的股数计算股数变化；申报市值只作报告期末金额，不将市值变化误判为买入或卖出。

- 前期无、本期有：显示“本期新披露”。
- 两期均有且股数增加/减少：显示“披露股数增加/减少”及股数差和变化百分比。
- 前期有、本期未见：显示“本期未披露”，不直接断言“清仓”或卖出。
- 上期数据缺失、修订关系不确定、证券映射不确定：显示“无法比较”及原因。

组合权重分母为该份完整、有效 13F 中全部已申报持仓的标准化市值总和，包含暂未映射到 MoneyMoney 股票代码的记录；标签必须写明“占已披露 13F 组合”，不能暗示占投资人全部资产的比例。若文件不完整或总值无法可靠计算，权重显示“—”。没有可靠 CUSIP/证券标识到 MoneyMoney 股票标的的映射时，记录进入未映射列表，不猜测股票代码。

### 2.3 申报主体与人物映射

- 查询和比较的主键是 SEC 申报主体 CIK，而不是名人姓名。
- 可提供人工核验过的展示别名（例如公众人物或基金品牌），但同时展示法律申报主体名称和 CIK。
- 无法核实某个人与申报主体关系时，只显示申报主体，不将该实体持仓归因给个人。
- 支持按申报主体名称或 CIK 搜索；精选名单只包含能解析到明确 CIK 和有效 SEC 申报的主体。首版不提供私人收藏或多用户名单管理。

## 3. 用户体验

入口放在股票工作区，名称为“大神持仓”，中间区显示当前选中的视图，右侧股票库仍负责标的选择。

### 3.1 投资人视图

- 显示经核验的精选申报主体列表、名称搜索和 CIK 搜索。
- 选中主体后显示最新有效 13F 摘要：法律主体名称、可核实别名、CIK、报告期、申报时间、修订标识、来源状态和持仓条数。
- 持仓表显示股票代码/名称、类别（普通股；无法确认的证券不混入股票表）、披露股数、申报市值、占已披露 13F 组合比例、上期股数、股数变化和变化状态。
- 可按持仓变化、申报市值和代码排序；选择股票可跳转到其股票工作区及 K 线，并保留来源报告期上下文。

### 3.2 热门股票视图

- 股票来源为当前有效热榜、自选和用户搜索结果；热榜本身不可用时明确显示来源状态，不使用固定七姐妹列表代替。
- 选中股票后显示精选主体及本次搜索选择的申报主体中匹配到的 13F 记录和相邻报告期变化，并可反向跳至申报主体完整持仓。
- 现有机构持仓雷达可作为独立的“机构概览”区域继续显示；每组记录单独展示来源、报告时间和状态，禁止跨来源拼接成貌似统一排名。
- 无匹配记录时说明范围是“当前跟踪申报主体未披露该股票”，不能推断该股票没有其他机构持有人。

### 3.3 状态与可追溯性

页面至少区分：来源不可用、延迟/季度披露、缓存、部分证券未映射、尚无有效申报、请求失败和当前市场不支持。每份申报及机构概览都能打开原始来源。空状态不得写成笼统的“暂无持仓”。

## 4. 数据流与接口边界

SEC 申报发现/读取 → 校验 CIK、报告期、表单类型和修订关系 → 解析披露记录并规范金额单位 → 用 CUSIP/稳定证券标识关联股票 → 保存申报元数据和规范化记录 → 比较相邻报告期 → API 返回带来源与时点的结果 → 股票工作区渲染。

对精选申报主体采用低频每日新申报检查；用户打开工作区先读取有明确状态的缓存，再按来源预算后台更新。管理员可显式重试当前主体。请求按 CIK 合并并限流，不在每次页面切换时重新下载完整历史；首版只保证当前和前一有效报告期的比较数据。修订文件按其 amendment 类型处理：明确的完整重述替代该报告期，明确的补充申报按 SEC 规则合并；无法判定类型或合并结果时保留原始证据并禁用该期变化比较。

新增只读接口建议：

- `GET /api/stocks/guru-holdings/managers?query=`：精选名单和主体搜索。
- `GET /api/stocks/guru-holdings/managers/:cik`：主体最新及前一有效报告期的持仓/变化。
- `GET /api/stocks/guru-holdings/symbols/:symbol`：指定股票在已跟踪申报主体中的披露记录。

响应包含 `market: "stocks"`、`instrument`（适用时）、`dataStatus`、`source`、`reportPeriod`、`filedAt`、`retrievedAt`、`sourceUrl`、`reason` 和证据引用。输入必须校验 CIK 与股票作用域；不提供跨市场回退。沿用现有研究存储和数据缓存，不另建平行业务数据库；SEC 请求需遵守其访问速率要求，并配置合规的请求标识。

## 5. 错误处理、安全与兼容

- SEC 拉取失败但有缓存时返回缓存及原始时点；无可用数据时返回明确失败状态和可重试信息。
- 修订申报须保留原始与修订文件的链接和状态，并按 SEC amendment 类型确定有效持仓；无法可靠解释修订关系时不生成变化结论。
- CUSIP 到股票代码映射不唯一或证券类别不受支持时，不进入股票汇总，可单独显示未映射原因。
- 访客只读访问公开持仓；管理员精选名单配置不得泄露现有私人组合、日记、任务或模拟订单。
- 切换投资人、股票或报告期时取消/忽略旧请求，避免旧主体数据覆盖当前视图。
- 不自动生成投资建议、策略发布或任何真实/模拟订单。

## 6. 验收标准

1. 两个视角均能从股票工作区互相跳转，并保持股票和申报主体身份一致。
2. 每条持仓显示报告期、申报时间、数据来源和 SEC 原文链接；季度时效及非实时属性醒目可见。
3. 连续报告期比较使用股数变化；价格变动不会被标成加仓/减仓；缺失记录只称“本期未披露”。
4. 组合权重明确以已披露 13F 为分母，不声称是完整资产配置；短仓不会被误显示为净仓位。
5. CIK、修订申报、无历史基线、缓存、来源失败、未映射证券和无匹配记录均有确定性状态。
6. 股票热榜或自选中的常见与非热门股票均显示真实匹配结果或具体空状态；不出现固定股票替代当前选择，也不跨市场串入。
7. 现有机构持仓雷达仍可用，其数据源不会与 SEC 13F 结果混并。
8. 访客仅能读取公开申报数据；功能不创建订单、不启用真实交易。
9. 完成 API/解析测试、股票工作区浏览器交互验收及项目标准测试、安全扫描后，再进入独立实现与发布流程。
