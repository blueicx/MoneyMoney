# 高影响事件提醒与结果通知设计

## 目标

降低高影响事件提醒的噪声，并在宏观事件公布实际值后补充一次结果通知。仅影响 Telegram 的高影响事件通知，不改变价格、风险、信号、日报和数据源恢复通知。

## 行为规格

### 倒计时提醒

- 提醒节点固定为：24 小时、12 小时、6 小时、3 小时、1 小时、30 分钟、10 分钟、5 分钟。
- 同一个聊天、同一个事件、同一个节点最多发送一次。
- 事件身份使用稳定的事件日期和标题组合；事件标题或时间改变时视为新事件，避免错误复用旧状态。
- 使用独立的 60 秒事件检查器，避免现有 10 分钟慢检查错过 5 分钟和 10 分钟节点。
- 进程运行期间正常跨过节点就发送对应提醒；如果一次检查跨过多个节点，只发送最新已到达节点，避免连续轰炸。
- 服务启动时只建立当前倒计时阶段基线，不补发启动前已经错过的节点；之后只等待下一个节点。这是用户确认的 B 策略。
- 保留现有聊天通知开关、暂停、免打扰时段和事件过滤行为。

### 事件结果

- 只处理已有 `actual` 实际值的事件；如果实际值尚未出现，不发送结果通知。
- 有 `forecast` 预期值时，比较实际值和预期值，输出“高于预期 / 低于预期 / 符合预期”。
- 根据指标的常规风险资产方向输出“偏利好 / 偏利空”；无法可靠映射或缺少预期时输出“方向不明”，不强行判断。
- 同一个聊天、同一个事件的结果最多发送一次；服务重启时把已经存在实际值的事件作为已观察基线，不重复补发。
- 结果通知包含事件标题、实际值、预期值、比较结果和方向判断。
- 结果通知沿用事件通知偏好、暂停和免打扰策略；被暂时抑制时不标记为已发送，后续仍可发送一次。

## 方向判定

采用保守的标题关键词映射：就业、GDP、零售、工业产出、PMI、消费者信心等“增长/就业更强”指标实际值高于预期时偏利好；CPI、PPI、PCE、通胀、失业率、失业金申请等“通胀/就业压力更高”指标实际值高于预期时偏利空。低于预期时反向处理。未匹配指标、利率决议和缺少预期值默认方向不明。

## 实现边界

- 在事件通知模块中增加可测试的倒计时阶段选择、阶段基线和结果方向判定纯函数。
- 在 Telegram 监控层增加独立事件定时器和两个内存去重状态：倒计时阶段状态、已观察/已发送结果状态。
- 不写入 SQLite，不改变现有数据库结构；本轮需求只要求运行期降噪和重启后的不补发策略。
- 事件日历拉取失败时静默保留现有行为，不发送不完整通知；下次轮询继续尝试。

## 测试与验收

- 先为倒计时节点、启动基线、跨越多个节点只取最新节点、结果比较和方向映射编写失败测试，再实现。
- 测试覆盖 24h、12h、6h、3h、1h、30m、10m、5m，以及已过期和缺少实际值/预期值的边界。
- 本地执行 `npm test`、`npm run build` 和 `git diff --check`。
- 部署后确认 `moneymoney.service` active，Telegram 轮询正常，并通过脱敏日志确认事件提醒监控启动；不发送测试消息给真实用户。
