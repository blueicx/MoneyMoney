# MoneyMoney 网页性能与请求治理设计

## 背景与证据

当前版本 `5d3fcc47171e425ebb63a8932c260a4b5084e5d7` 已部署并完成生产只读巡检。工作区检查显示：

- `src/web/public/modules/dashboard-runtime.js` 约 817 KB，是多市场、多工作区的共享浏览器运行时。
- `src/web/public/index.html` 约 130 KB，底部仍加载多份工作区脚本；部分脚本有 `defer`，但仍会在初始页面中下载和执行。
- `src/web/server.ts` 约 674 KB，包含大量接口及监控调度。本轮不重构服务端路由，以限制风险。
- 页面已有部分请求取消和上下文令牌，但覆盖分散；需要先通过浏览器网络记录确认实际首屏请求及重复请求，再决定迁移顺序。

用户已同意优先处理网页变慢。本轮目标是降低冷启动和切换工作区的请求/执行负担，同时保持当前外观、交互和业务行为。

## 目标

1. 建立可重复的冷/热加载基线：记录页面可操作时间、首屏脚本下载与执行量、初始无关 API 请求数、工作区切换延迟和长任务。
2. 首屏只启动当前市场、当前工作区、右侧标的库及必要共享能力；未打开的工作区不得提前发起专属数据请求。
3. 工作区切换时取消旧上下文的可取消请求；迟到响应不得更新新市场或新标的。
4. 离开工作区或页面进入后台时暂停该工作区非必要轮询/绘制，返回后从当前上下文安全恢复。
5. 只缓存明确公开且允许短时复用的数据；私人、账户、订单、日记和管理员接口仍使用 `no-store`。
6. 不改变三个主题、左/中/右区域职责、四市场隔离、访客权限、现有模拟跑单配置或任何交易执行边界。

## 非目标

- 不整体重写 `dashboard-runtime.js` 或 `server.ts`。
- 不引入 React、Vite 或新的运行时框架。
- 不改市场策略、报价来源、风控、数据库结构和 API 业务语义。
- 不做视觉改版；现有主题和工作区内容边界保持不变。
- 不把首屏性能目标解释为市场数据实时性保证。

## 方案与组件边界

采用渐进式浏览器侧治理：

1. **性能基准与回归工具**：扩展现有 Chromium 冒烟脚本，用请求拦截/Performance API 记录启动与切换数据；测试使用隔离 fixture，不访问真实下单、Telegram 写接口或管理员变更接口。
2. **工作区依赖清单**：在现有工作区路由基础上建立显式映射，列出共享启动模块、各工作区所需脚本、初始化入口及轮询资源。映射缺失时保持现状加载，不允许静默漏功能。
3. **按需模块加载**：把可独立初始化的研究、期权/合约、事件和比较等脚本改为首次进入时加载一次；保留共享的市场壳层、当前 K 线入口和右侧库在首屏可用。
4. **上下文请求生命周期**：通过统一的工作区/市场上下文代次或 AbortController 管理已标记为可取消的请求。无法安全取消的共享请求可以完成，但结果必须校验上下文代次后才能写入 DOM。
5. **轮询与页面可见性**：工作区专属轮询仅在对应面板可见时活动；`visibilitychange` 后台暂停非必要轮询和图表绘制，回到前台时重新校验数据新鲜度再刷新。
6. **缓存边界**：公共行情摘要继续沿用服务端已有短缓存；私人 API 不启用共享缓存。前端只对同一上下文、短生命周期的可复用请求做去重，不延长敏感数据生命周期。

### 数据流

`用户进入市场/工作区 → 解析依赖 → 一次性加载模块 → 按当前上下文请求数据 → 返回时核验上下文代次 → 渲染当前视图`

`离开工作区/切换市场 → 中止旧请求 + 停止专属轮询 → 丢弃迟到响应 → 新上下文启动`

## 用户可见行为

- 进入某市场时中心区仍只显示该市场、该工作区内容；首次打开未加载的工作区显示现有风格的轻量加载状态。
- 返回已访问工作区时保留原有筛选、滚动位置与视窗；数据是否刷新由现有新鲜度状态决定。
- 旧请求被取消不显示错误 toast，也不能覆盖当前标的。
- 页面回到前台时，如果数据已过期则刷新；未过期则保留当前显示，不强制跳回最新 K 线。
- 数据源失败、缓存、空结果和不支持状态沿用当前明确文案，不伪造数据。

## 验收标准

### 行为与正确性

- 初始股票驾驶舱不发出期权链、预测市场、研究、AI 跑单等未激活工作区的专属请求；公共驾驶舱及当前市场右侧库请求允许发生。
- 首次进入一个工作区时其脚本最多加载一次；之后往返不重复下载或重复注册监听器。
- 快速切换 `stocks → crypto` 时，旧股票响应不能写入虚拟币视图；请求取消与代次校验至少有一项能防止污染。
- 隐藏工作区及后台页面不执行该工作区的非必要轮询/图表重绘；回到前台能够恢复。
- 访客仍无法读取私人工作区；私人 API 响应没有新增可缓存头。
- 四市场选择、K 线、右侧库、三个主题、移动布局和工作区专属内容通过现有 Chromium 矩阵。

### 性能

- 冷、热加载及每个市场至少重复三次，报告中位数和离散情况。
- 相对本轮变更前基线，首屏可操作时间中位数目标改善至少 30%；初始下载并执行的非必要工作区脚本/请求至少减少 30%。
- 若可靠浏览器基线不能支持上述目标，必须报告实测值和瓶颈，不用代码体积下降替代用户体验指标，也不把未达目标称为完成。

### 发布

- `npm test`、`npm run build`、`npm run smoke:web`、`npm run smoke:auth`、`npm run smoke:browser`、`npm run security:scan`、`git diff --check` 全部通过。
- 生产只读 Chromium 验收通过后才提交、推送和部署；部署前保存远端 dist 备份和回滚目录，部署后核验正式域名、commit、健康状态及资源哈希。
- 只重启 `moneymoney.service`，不修改数据库、数据湖、Telegram 发送状态、环境密钥和模拟跑单配置。

## 风险与处理

- **共享脚本有隐式全局依赖**：只按可证明的工作区边界拆分；逐个迁移并补模块只初始化一次测试，保留安全的 eager fallback。
- **切换导致被用户编辑的表单丢失**：只停止请求/轮询，不卸载可见 DOM；保留已编辑状态与原有恢复机制。
- **前台恢复触发请求风暴**：每个工作区设置单飞刷新和最小刷新间隔，复用现有请求缓存。
- **性能数据受外部来源波动影响**：对比同设备、同浏览器、同网络，分开记录静态加载与上游 API 等待时间。
- **部署回归**：通过本地四市场矩阵与正式域名只读矩阵；若健康或 Hash 不符，执行 dist 回滚，不碰运行时数据。

## 自检

- 功能目标均对应到性能测试、浏览器行为测试或部署检查；没有把服务端整体拆分混入本轮。
- 范围限定在前端启动/请求生命周期及相关自动化测试，可由单一实现计划完成。
- 目标统一使用“当前市场/工作区上下文代次”概念；不变量是迟到结果不能改写新上下文。
- 工作区依赖表必须从实际初始化调用和网络请求测量中导出，不按文件名猜测业务依赖。
