# MoneyMoney 研究终端扩充设计

> 设计日期：2026-09-12
> 设计状态：待用户审查

## 目标

把 MoneyMoney 从“多市场功能集合”推进为一条可复现、可解释、可追踪的研究闭环：

`选标的 → 看详情 → 筛选/比较 → 保存研究 → 回测 → 模拟持仓 → 预警 → 复盘`

本轮以稳定性和可信度为前置条件，保持股票、期权、虚拟币、预测市场和总体工作区的物理隔离；不开放真实交易，不把不可用数据伪装成可用数据。

## 当前基础与明确缺口

当前已有市场作用域、左侧功能导航、右侧股票标的库、七姐妹快捷入口、统一标的、免费股票数据源、统一模拟账本、回测入口、提醒、AI 作用域和 Telegram 作用域。

本轮重点补齐：

1. 数据源状态和缓存年龄没有在每个功能卡片上形成统一可读的契约。
2. 详情、筛选、比较、研究笔记、回测、模拟和提醒之间还不是一条连续操作链。
3. 回测需要进一步区分股票 T+1、虚拟币 24/7、期权历史 IV/Greeks 和预测市场结算语义。
4. 首屏加载、外部源超时、重复请求和 readiness 慢的问题需要统一治理。
5. 期权、虚拟币和预测市场还需要继续补专属深度，但不能回退显示其他市场字段。

## 设计原则

- **作用域优先**：任何数据、缓存、筛选模板、比较快照、候选、回测和提醒都必须带 `scope`；跨市场操作只允许经过明确的标准化字段映射。
- **标的优先**：中间区只展示当前工作区和当前标的的内容；标的选择统一放入右侧库或对应市场的专属库。
- **数据诚实**：每个结果携带来源、更新时间、新鲜度和不可用原因；源失败时允许局部降级，但禁止用其他市场数据填充。
- **研究可复现**：筛选、回测和模拟记录参数、策略版本、数据快照标识和费用/滑点假设。
- **免费源可运行**：免费公开源是默认路径，付费或需要 Key 的源只能作为可选增强。
- **只读安全边界**：Guest 可以读取公开研究数据，不能修改自选、提醒、持仓或执行交易。

## 总体布局

### 左侧导航

左侧保留全局市场和功能区导航：总体、股票、期权、虚拟币、预测市场、自选，以及当前市场允许的研究功能。进入专属工作区后，其他市场功能不在中间内容区渲染。

### 中间工作区

中间只渲染一个当前功能：行情总览、标的详情、内部人、机构、分析师、基本面、空头、市场宽度、期权链、虚拟币衍生品或预测市场详情。每个功能有自己的加载、空数据和错误状态。

### 右侧标的库

右侧是上下文控制区，按当前市场显示：固定热门标的、自选、模拟持仓、搜索、最近访问和候选库。点击标的只改变当前 `instrument`，不改变当前工作区；工作区负责重新加载自己的专属数据。

## 四条实现轨道

### 轨道 A：数据可信度与加载性能

建立统一 `DataStatus` 契约：

```ts
type DataStatus = {
  state: 'live' | 'delayed' | 'cached' | 'degraded' | 'unavailable';
  source: string;
  observedAt: string | null;
  expiresAt: string | null;
  latencyMs: number | null;
  reason: string | null;
};
```

所有市场服务返回 `data + status`，前端统一显示状态徽章、来源、时间和重试入口。缓存层实现按 `scope + source + key` 隔离的 fresh/stale/expired、并发去重、超时降级、SWR 和条件请求；当前请求取消后禁止旧市场或旧标的结果回填。

性能验收以真实页面为准：首屏不等待未使用的工作区，专属工作区只请求自身数据；公共接口有耗时和失败率记录；外部源超时能在固定时间内显示结构化不可用。

### 轨道 B：详情、筛选、比较和研究闭环

统一详情接口以 `InstrumentRef` 为入口，返回行情、图表、事件、新闻、研究指标和来源状态。筛选器按市场维护字段白名单，模板保存 `scope`、字段、排序、分页和创建时间；比较只允许同一市场，跨市场只显示明确的标准化字段。

结果可以执行四种动作：

1. 加入当前市场自选。
2. 保存到当前市场候选库。
3. 创建当前市场提醒。
4. 带着筛选/标的/参数进入回测。

候选库保存来源快照、筛选条件、策略版本和进入时间，点击候选重新进入对应市场和标的，不跨市场复用。

### 轨道 C：回测、模拟盘和风险分析

统一回测请求保留市场专属策略适配器：

- 股票：T+1、复权、分红拆股、停牌、手续费、滑点、基准。
- 虚拟币：24/7、资金费率、手续费、杠杆、爆仓和盘口滑点。
- 期权：历史链、到期、IV、Greeks、行权和策略 Payoff；缺少关键历史数据时返回 `unavailable`，不生成伪回测结果。
- 预测市场：YES/NO 价格、概率、价差、流动性、截止时间和结算结果。

结果统一输出收益曲线、交易明细、CAGR、Sharpe、Sortino、最大回撤、胜率、盈亏比、换手率、费用滑点影响和基准差异，并保留实验参数、数据快照与策略版本。

模拟盘沿用只做本地纸面交易的边界，增加组合集中度、市场敞口、策略归因、回撤恢复和压力测试；回测结果可复制为模拟策略，但不能直接触发真实订单。

### 轨道 D：AI、Telegram、提醒和市场专属深度

AI 和 Telegram 共用同一个 `MarketContext`：`scope`、`workspace`、`instrument`、筛选条件、持仓摘要和数据状态。所有建议必须能追溯来源，并通过结构化动作回到详情、候选、提醒或回测页面。

提醒支持单标的、自选组、筛选结果和数据源状态，保留去重、冷却、静默和投递审计。Telegram 的菜单、搜索、详情、回测、持仓和提醒回调都必须携带聊天级市场作用域。

市场深度按照专属能力扩充：

- 股票：财报、内部人、机构、分析师、空头、市场宽度、行业轮动。
- 期权：期权链、IV 期限结构、Skew、GEX、Max Pain、PCR、策略构建器。
- 虚拟币：资金费率、OI、爆仓、多空比、盘口、交易所价差和链上指标。
- 预测市场：事件树、YES/NO 历史、订单簿、价差、流动性和结算证据。

## 错误处理与权限

- 单个源失败只影响对应字段或卡片，整体页面仍显示其他已成功数据。
- 超时、限流、无历史数据和需要 Key 分别使用不同的不可用原因。
- 切换市场或标的时取消旧请求，旧响应即使返回也不得更新当前 DOM。
- Guest 的 GET 公开研究接口返回 200；自选、提醒、候选、持仓和回测写接口返回 403。
- 真实交易、真实持仓同步、AI 自动下单和券商连接不属于本轮范围。
- 发布只替换构建后的 `dist`，先备份现有产物，再重启服务并核对健康、HTTPS、Hash 和访问控制。

## 测试策略

### 单元和接口测试

- 每个数据源适配器验证 `DataStatus`、超时、缓存、降级和字段白名单。
- 每个市场验证统一详情、筛选、比较、候选、回测和提醒不会跨作用域。
- 回测验证费用、滑点、市场交易时间、数据缺口和不可用状态。
- Guest 验证公开 GET 与所有写操作的边界。
- Telegram 验证聊天级 scope 在菜单、搜索、详情、回测和提醒回调中保持不变。

### 浏览器验收

建立五市场 × 主要工作区的冒烟矩阵，至少覆盖：

1. 右侧库选标的后中间只出现当前工作区内容。
2. 股票、期权、虚拟币和预测市场不显示彼此专属字段。
3. 外部源不可用时显示状态、原因和重试，不显示假数据。
4. 首屏不等待隐藏工作区，切换标的不产生旧内容回填。
5. 回测结果能进入候选、自选、模拟盘和提醒流程。

### 发布门

每条轨道完成后必须通过构建、完整测试、安全扫描、`git diff --check`、本地浏览器冒烟；合并发布前再进行公网健康检查、Guest 读写边界、远端产物 Hash 和真实浏览器验证。

## 分阶段交付

### 第一阶段：可信数据与研究入口

先完成轨道 A，并交付轨道 B 的统一详情、筛选模板、同市场比较和候选库。验收重点是数据状态可见、加载明显变快、标的上下文不丢失。

### 第二阶段：可解释回测与模拟组合

完成轨道 C 的股票和虚拟币可靠回测，补齐组合风险和绩效归因；期权和预测市场在历史数据不足时优先完成诚实的不可用边界，再逐步接入专属历史链路。

### 第三阶段：AI/Telegram 闭环与专属深度

完成轨道 D 的上下文一致性、提醒审计和 Telegram parity，再按数据可得性扩充期权、虚拟币和预测市场深度。

## 用户验收标准

用户在任一市场选择标的后，能够在同一作用域内完成“看详情、筛选/比较、保存候选、回测、模拟、设置提醒”；页面不会显示其他市场的专属内容；数据不可用时能看到明确原因；刷新和切换标的不会长时间卡住或出现旧数据。
