# 分析师共识与基本面质量扩充设计

**日期：** 2026-09-12  
**状态：** 已获用户确认设计方向，等待规格审查  
**范围：** 股票市场的“分析师共识”和“基本面质量”两个工作区

## 1. 目标

把两个现有雷达从“指标摘要卡片”扩展为可追溯的单股研究工作台：用户选择右侧股票库中的标的后，可以看到分析师具体动态、目标价变化、基本面历史趋势、风险提示、数据来源和数据新鲜度。

本次不改变市场作用域、股票选择方式、真实交易边界或当前 MoneyMoney 主题；不把缺失的来源内容猜测成分析师观点。

## 2. 用户体验与布局

### 2.1 分析师共识

当前功能卡片保留现有标题、现价、共识评分、评级分布和解读，并新增以下内部区域：

1. **核心摘要**：共识评分、覆盖分析师数量、买入/卖出占比、中位目标价、平均目标价、隐含空间、三个月买入变化、数据年龄。
2. **目标价区间**：低位、均值、中位数、高位和覆盖数量，用水平区间条表达当前价格相对目标价的位置；数据不足时显示“暂无足够目标价”。
3. **分析师动态**：按日期倒序显示最近动态，每条包含分析师姓名、机构、日期、动作、新旧评级、原目标价和新目标价。
4. **观点摘要**：来源提供公开观点文本时显示经过长度限制的短摘录，并附来源链接；来源没有观点文本时，显示由结构化动作生成的事实摘要，例如“某机构将评级从 X 调整为 Y，目标价从 A 调整为 B”，不生成未经来源支持的主观观点。
5. **历史共识趋势**：使用现有历史评级数据，显示最近月份的评分和买入占比变化，优先采用轻量 SVG/CSS 图形，不新增重量级图表依赖。
6. **来源与状态**：显示来源、更新时间、数据年龄、置信度和部分字段不可用说明。

刷新按钮与当前状态徽章位于同一标题行：刷新按钮在状态徽章左侧，状态徽章继续位于右侧，并保持垂直居中。外层折叠标题框不显示，只保留内部数据卡片。

### 2.2 基本面质量

当前功能卡片保留评分、信号和解读，并新增以下内部区域：

1. **质量指标摘要**：营收增长、毛利率、经营利润率、净利率、经营现金流/净利、应计占比、流动比率、负债/资产和 ROE。
2. **历史趋势**：使用现有年度历史数据展示营收、净利率、经营现金流率和流动比率的变化；只有一个年度时改为“单期数据，暂不足以判断趋势”。
3. **盈利质量解释**：把现金转换、应计、利润率和负债情况拆成“支持因素”和“风险因素”，每项显示触发原因和对应数值。
4. **财报新鲜度**：显示财年截止日、申报日、数据年龄和缺失字段列表；缺失字段不影响其他指标渲染。
5. **来源与限制**：保留 SEC EDGAR XBRL/10-K 来源和“研究背景、不构成买卖指令”的限制说明。

刷新按钮与状态徽章采用与分析师共识完全相同的标题行布局。

## 3. 数据契约与数据流

### 3.1 分析师数据

沿用 `src/features/analyst-consensus.ts` 的现有缓存和 StockAnalysis 公共页面解析流程，扩展 `RecentAnalystAction`：

- `sourceUrl: string`：对应公开来源地址。
- `sourceExcerpt: string | null`：来源明确提供时的短摘录，没有时为 `null`。
- `summaryZh: string`：由机构、动作、评级和目标价等结构化字段生成的事实摘要。

`AnalystConsensusSnapshot` 保留现有 `recentActions`、`history`、`priceTargets` 和评分字段，不改变已有调用者。来源没有可验证观点文本时，`sourceExcerpt` 必须为空，前端只显示 `summaryZh`。

数据流为：右侧股票库选择标的 → 当前股票工作区和 URL 同步 → `/api/stock/analyst/:symbol` → 后端缓存/解析 → 前端渲染核心摘要、目标价区间、动态列表和历史趋势。刷新只重新请求当前标的，不改变工作区或选中的股票。

### 3.2 基本面数据

沿用 `src/features/fundamental-quality.ts` 的 SEC EDGAR Company Facts 数据和现有年度筛选逻辑。后端保留现有 `metrics`、`history`、`missingFields`、`confidence` 和 `dataAgeDays` 字段，并增加结构化的质量解释字段：

- `supportingFactors: Array<{ label: string; value: string; reason: string }>`。
- `riskFactors: Array<{ label: string; value: string; reason: string }>`。

这些字段只基于已计算的指标和既有阈值生成，避免前端重复实现评分规则；字段为空时前端显示明确的“暂无明显触发项”。

数据流为：右侧股票库选择标的 → `/api/stock/fundamentals/:symbol` → SEC 数据适配、年度历史整理、质量因素分类 → 前端渲染指标、趋势、支持因素、风险因素和来源状态。

## 4. 错误处理与边界

- 分析师页面没有动态文本时，不显示“观点原文”空框，改显示结构化事实摘要。
- 分析师目标价、评级历史或现价任一部分缺失时，其余区域继续显示，并在对应区域标记“数据不足”。
- 基本面某些 XBRL 标签缺失时，指标显示 `—`，不把缺失当作零值；`missingFields` 明确列出缺失字段。
- SEC、StockAnalysis 或行情请求失败时，保留当前股票和当前工作区，显示可重试状态与来源，不回退到其他市场或其他股票的数据。
- 观点摘录限制长度并进行 HTML 转义；来源链接只允许生成自已确认的公开来源地址。
- 现有缓存 TTL、请求失效令牌、市场作用域隔离和真实交易关闭边界保持不变。

## 6. 验收标准

1. AAPL、MSFT 等固定股票和右侧搜索选中的股票都能独立加载两个工作区。
2. 分析师动态至少能显示已有结构化字段：姓名、机构、日期、动作、评级变化和目标价变化；没有公开文本时不显示虚构引语。
3. 基本面区域能显示指标、历史数据、支持因素、风险因素、缺失字段和数据新鲜度。
4. 两个工作区均不显示外层折叠标题框；刷新按钮在状态徽章左侧且垂直居中，内部卡片保持当前主题。
5. 切换市场、切换股票、重复刷新和接口部分失败不会串用旧标的数据。
6. `npm run build`、`npm test`、`npm run smoke:web`、`npm run security:scan`、`git diff --check` 全部通过。
7. 浏览器实测两个工作区的真实渲染、股票切换、来源状态和刷新位置；通过后才部署 VPS，并保留可验证备份和回滚目录。
