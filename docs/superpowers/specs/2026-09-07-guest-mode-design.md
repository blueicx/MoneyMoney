# MoneyMoney 访客只读模式设计

日期：2026-09-07
状态：待实现

## 目标

在现有登录门禁之外增加“访客进入”入口，让未注册或不需要管理权限的用户能够浏览公开市场信息，同时确保配置、凭据、Telegram 和交易能力仍只对管理员开放。

## 用户体验

- 登录页增加“访客进入”按钮，与管理员账号登录并列。
- 进入后页面显示“访客模式 · 只读”提示，并提供返回管理员登录的入口。
- 访客可以查看市场、行情、新闻、事件和分析等公开信息。
- 访客界面隐藏设置、API Key、Telegram 管理、模拟交易、真实交易和自动化操作入口。
- 访客尝试直接调用受限接口时，服务端返回 HTTP 403 和明确的只读权限提示。

## 认证与令牌

- 新增 `POST /api/auth/guest`，不接收账号或密码，只签发带 `role: guest` 的现有 HMAC-SHA256 登录令牌。
- 访客令牌使用独立的短期有效期，默认 2 小时；令牌仍使用现有 HttpOnly、SameSite 和 Secure Cookie 规则。
- `AuthPayload` 增加角色字段；管理员令牌角色为 `admin`，兼容历史无角色令牌时按管理员处理。
- `/api/auth/status` 和 `/api/auth/me` 返回脱敏的角色信息，前端据此展示访客状态。
- 访客令牌沿用现有登出黑名单和签名校验逻辑。

## 服务端权限边界

- 访客只能访问明确列入 allowlist 的 GET 公开数据接口。
- 访客拒绝所有 POST、PUT、PATCH、DELETE 请求。
- 访客拒绝设置、凭据、Telegram、钱包、持仓、模拟盘、真实交易、自动化、研究私有记录和运行控制等接口，即使这些接口使用 GET。
- 管理员路径和现有登录行为保持不变；访客限制放在统一认证中间件之后，避免遗漏单个路由。
- LAN 访问令牌中间件和健康检查规则保持不变；访客模式不绕过网络层访问控制。

## 前端行为

- 登录页调用访客接口后保存服务端 Cookie，并按 `next` 参数进入首页。
- 首页启动时读取认证角色；访客状态下增加只读提示，并隐藏管理入口。
- 前端不把访客身份当作管理员身份，也不向访客展示配置状态或敏感运行状态。
- 当访客收到 403 时显示“访客模式仅支持浏览”，不自动重复请求或跳回登录页。

## 错误处理与兼容性

- 访客签发失败返回统一 JSON 错误，不暴露签名密钥或环境配置。
- 访客令牌过期沿用现有过期处理，跳转登录页并保留原 `next`。
- 管理员登录、退出、续期、API 认证和 LAN 访问回归行为不得改变。
- 不新增数据库表；角色仅存在于签名令牌中。

## 测试与验收

- 认证单元测试：访客令牌包含 guest 角色、签名校验、过期、登出黑名单和历史管理员令牌兼容。
- 权限测试：访客允许公开 GET，拒绝所有写请求及敏感 GET；管理员仍可访问原受保护接口。
- 前端静态/集成测试：登录页有访客入口，首页显示只读状态并隐藏管理入口。
- 本地运行 `npm test` 和 `npm run build`。
- 部署后验证：域名登录页能进入访客模式；公开行情接口可用；设置、Telegram 和交易接口返回 403；管理员登录不受影响。
