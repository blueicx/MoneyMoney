# Telegram 底部键盘菜单分页设计

日期：2026-09-04

## 目标

将 Telegram 底部功能键盘从当前的长菜单改为每页最多 4 行功能按钮，并提供上一页、当前页、下一页导航。所有现有功能和命令保持不变。

## 用户体验

- 第 1 页：总览、风险中心、今日总览、最新信号。
- 第 2 页：搜索市场、事件日历、自选市场、信号解释、模拟盘、研究工作区、交易复盘、研究日志。
- 第 3 页：数据源健康、历史表现、提醒设置、定时摘要、自动化状态、系统状态、通知测试、帮助。
- 每页底部增加导航行：`⬅ 上一页`、`菜单 X/3`、`下一页 ➡`；第一页禁用上一页，最后一页禁用下一页。
- Bot 重启后页码不持久化，聊天首次交互从第 1 页开始。
- 现有菜单文字命令、斜杠命令和回调行为不变；导航按钮只切换键盘，不触发业务操作。

## 架构与数据流

- 将静态 `TELEGRAM_BOTTOM_MENU` 改为按页生成键盘的函数，输入页码和聊天 ID，输出 Telegram reply keyboard。
- 使用进程内 `Map<chatId, page>` 保存当前页；页码写入前后统一限制在 1 到 3。
- 导航按钮通过现有文字菜单分发机制进入 `menu_prev` / `menu_next` 处理器，处理器更新对应聊天的页码并返回新的键盘。
- `telegramReply` 和需要底部键盘的回复统一从当前聊天页生成键盘；内联回复保持现状，不额外带底部分页键盘。
- 原有 `TELEGRAM_MENU_COMMANDS` 映射继续保留，功能按钮的文本到命令映射不变。

## 错误处理与边界

- 缺失或非法聊天 ID 时使用第 1 页，不让一个聊天的页码影响另一个聊天。
- 页码超出范围时钳制到最近合法页。
- 用户快速重复点击导航时，结果仍只能落在合法页范围内。
- 进程重启丢失页码是预期行为，不写入 Token、数据库或交接文档。

## 验证

- 新增测试验证：页码范围、每页功能行数不超过 4、导航边界、聊天隔离、现有菜单命令仍全部存在。
- 先运行新测试并确认在实现前失败，再实现最小变更。
- 实现后运行新测试、完整 `npm test`、`npm run build`，并对实际 Telegram 键盘执行一次翻页和原有功能按钮交互验证。

## 非目标

- 不改变 Telegram Bot Token、轮询、权限、VPN、Web 登录门禁或任何业务处理逻辑。
- 不把分页状态持久化到远端 SQLite 或文件。
