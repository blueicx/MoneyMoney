# 左侧固定市场功能区设计规格

**状态：** 已获用户确认，等待书面规格审查

## 目标

参考 [tick-stock-panel](https://github.com/shy3130/tick-stock-panel) 的左侧固定功能区，把 MoneyMoney 当前分散在顶部横栏、底部导航和页面卡片中的功能，整理成一个稳定的左侧工作区导航。顶部继续负责市场切换，左侧负责进入功能，右侧只展示当前市场和当前标的的数据。

## 参考结论

参考项目公开 README 将“看板、自选、回测、监控中心、个股分析、数据与设置”组织为连续的研究闭环；其源码中的 `Layout.tsx` 使用可折叠侧栏、持久化导航状态和可展开的自选分组，`Backtest.tsx` 使用页面头部操作区与内部研究视图切换，`Watchlist.tsx` 提供表格/卡片双视图、分组和列配置。这些是可迁移的交互结构。

不直接迁移 A 股专属口径，包括涨停、连板、龙虎榜、同花顺风向标和只适用于 A 股的指标名称。MoneyMoney 仍以 `overview / stocks / options / crypto / prediction / watchlist` 为市场作用域；宏观、新闻日历、证据工作台等继续属于通用工具。

## 设计决策

### 1. 页面骨架

保留当前顶部两层横栏：

1. 第一层是市场栏：总体、股票、期权、虚拟币、预测市场、自选、搜索、设置。
2. 第二层是通用工具栏：证据工作台、新闻日历、宏观、回测、策略对比、提醒、巨鲸监控等。

主内容改成三段式：

```text
┌──────────────────────────────────────────────────────────────┐
│ 市场栏：当前市场作用域                                        │
├──────────────────────────────────────────────────────────────┤
│ 通用工具栏                                                    │
├───────────────┬──────────────────────────────────────────────┤
│ 左侧市场功能区 │ 右侧当前页面                                 │
│ 当前市场菜单   │ 当前市场大盘 / 当前标的 / 当前功能内容         │
└───────────────┴──────────────────────────────────────────────┘
```

桌面端左栏宽度为 224px，支持折叠为 56px 图标栏；移动端改为抽屉，不新增一套功能入口。当前底部核心导航保留为移动端快捷入口，但其内容从同一份市场菜单生成。

### 2. 左侧菜单模型

左栏不是跨市场混合内容，而是“固定位置 + 作用域菜单”。菜单分为通用的功能组和当前市场专属组：

```ts
type WorkspaceTab =
  | 'overview' | 'radar' | 'analysis' | 'backtest'
  | 'watchlist' | 'positions' | 'risk' | 'search';

type MarketWorkspaceItem = {
  id: WorkspaceTab;
  label: string;
  icon: string;
  scopes: MarketScope[];
  requiresInstrument?: boolean;
};
```

基础菜单对所有市场保持位置一致：行情总览、雷达、分析、回测、自选、模拟持仓、风险。市场专属菜单由作用域决定：

- 股票：市场宽度、内部人交易、机构持仓、分析师共识、基本面、空头利息。
- 期权：期权链、波动率、Greeks、到期结构、期权回测；数据缺失时显示该市场的明确不可用状态。
- 虚拟币：交易所行情、资金费率、未平仓量、链上/巨鲸、币种回测。
- 预测市场：预测雷达、事件详情、预测回测。
- 总体：跨市场概览和通用摘要，但不把总体内容伪装成某一个市场的专属数据。

宏观、新闻日历、证据工作台、策略对比、提醒和巨鲸监控仍只在顶部通用工具栏出现，避免在左栏重复。

### 3. 路由和当前标的

URL 作为可恢复状态源：

```text
/?market=stocks&workspace=insider&instrument=AAPL
```

切换市场时执行以下顺序：

1. 校验目标工作区是否允许在新市场显示。
2. 保留能跨市场复用的工作区（如行情总览、搜索、回测入口），清除不适用工作区。
3. 清除旧市场的当前标的，除非该标的已通过统一标的解析器确认属于新市场。
4. 使用 `scope + workspace + instrument` 组成请求和缓存键。
5. 取消旧作用域的未完成请求，展示新作用域的加载骨架。

从左侧自选、模拟持仓、搜索结果或雷达卡片点选标的时，统一写入当前市场和标的上下文。右侧每个数据组件都必须读取这个上下文，不再跳转到“热门股票”或沿用上一市场的数据。

### 4. 视觉和状态

左栏沿用 MoneyMoney 现有深色金色主题与 CSS 变量，不复制参考项目的蓝紫配色。每个菜单项支持：激活、悬停、加载、无数据、权限不足五种状态；状态只影响当前菜单项，不用全页默认白色控件。

右侧页面统一使用参考项目的紧凑信息密度：页面头部显示市场、标的、数据源和刷新时间；卡片显示来源标签和可用性；长列表使用表格/卡片切换；回测显示参数、净值曲线、交易明细和错误原因。

### 5. 数据和权限边界

后端提供作用域菜单配置或统一共享配置，前端不能自行把股票菜单拼到虚拟币页面。每个数据 API 继续校验 `scope` 和标的类型：

- 股票接口只接受股票标的。
- 期权接口只接受期权标的，暂无数据时返回结构化 unavailable。
- 虚拟币接口只接受虚拟币交易对。
- 预测接口保留预测市场独有的 YES/NO 语义。
- 访客只能读取允许的 GET 接口，左栏不显示写入、下单和敏感设置入口。

## 交互流程

1. 用户点击顶部“股票”，左侧菜单刷新为股票工作区，右侧加载股票大盘。
2. 用户点击左侧“内部人交易”，右侧显示股票内部人数据；搜索框就在该工作区内，结果点击后仍停留在股票作用域。
3. 用户点击左侧“回测”，回测表单默认使用当前股票标的；切换到虚拟币后，表单、历史数据、策略说明和结果全部改为虚拟币语义。
4. 用户点击顶部“宏观”，进入通用工具，不改变当前市场作用域，也不把宏观数据混入股票/期权/虚拟币专属雷达。
5. 用户在移动端打开左侧抽屉，选择工作区后抽屉自动关闭，右侧内容保持同样的作用域上下文。

## 非目标

- 不把 MoneyMoney 改成 React 或复制参考项目的 Python/FastAPI/Polars 技术栈。
- 不一次性实现参考项目全部 A 股策略、因子挖掘、连板梯队或第三方数据源。
- 不新增未经验证的数据源，不用其他市场数据填补当前市场缺口。
- 不改动 Nginx、TLS、VPN、Telegram 轮询所有权或运行密钥。

## 验收标准

- 桌面端可看到左侧固定功能区，折叠后仍能识别当前市场和激活项。
- 切换股票、期权、虚拟币、预测市场时，左侧市场专属菜单和右侧标题/大盘/数据源同步变化。
- 从任一左侧工作区内搜索并点选标的后，当前工作区显示该标的，不跳转到其他市场或热门股票。
- 股票页不出现资金费率、未平仓量或预测市场事件；虚拟币页不出现 SEC 内部人、机构持仓或股票财报；预测页不出现股票/币种回测字段。
- 宏观、新闻日历、证据工作台只保留在通用工具栏，切换宏观不污染市场作用域。
- 刷新页面或复制 URL 后，市场、工作区和标的可恢复；旧作用域请求不会覆盖新作用域内容。
- 桌面折叠、移动抽屉、加载骨架、不可用状态和访客只读状态均通过浏览器验收。

## 计划前审查问题

本规格采用“顶部市场栏 + 顶部通用工具栏 + 左侧固定市场功能区 + 右侧内容”的结构。进入实现计划前，请确认左侧菜单的分组和作用域边界是否符合你的预期。
