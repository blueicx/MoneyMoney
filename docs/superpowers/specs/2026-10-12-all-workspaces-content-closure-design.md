# MoneyMoney 全工作区内容闭环设计

日期：2026-10-12
状态：待用户审阅
基线：`codex/research-closure-all`，当前 B 版图表/工作区布局

## 目标

系统性优化四个市场和全部共用工作区，让每个工作区的内容与其职责一致、数据有来源、空状态可解释、后续操作可追溯。以现有注册表中的 30 个 `WorkspaceId` 为清单，逐批完成，不用增加入口数量代替功能交付。

继续保持默认市场驾驶舱、当前 B 版布局与三个主题；四市场严格隔离，公开访客只读，模拟盘与真实交易边界不变。

## 工作区范围

- 股票：行情与选股、市场事件与新闻、市场宽度、内部人交易、机构持仓、大神持仓、分析师共识、基本面质量、空头利息。
- 期权：事件与新闻、期权链、隐含波动率、Greeks。
- 虚拟币：行情与 K 线、事件与新闻、永续与交割合约、资金费率、未平仓量、链上数据、主动资金流。
- 预测市场：事件与新闻、预测雷达。
- 共用：市场总览、市场雷达、标的分析、筛选与比较、策略回测、风险监控、可信决策、研究实验室、自选行动、我的自选、我的持仓。

以上共计 30 个唯一工作区；“事件与新闻”按当前市场上下文显示，不共用或回填其他市场数据。

## 设计决策

### 方案比较

1. 一次性整体重写：表面统一较快，但改动面大，容易破坏已验收的工作区、主题和图表行为。
2. 每个工作区独立增加新卡片：交付快，但会造成重复数据口径、孤立入口和功能区串内容。
3. **以现有工作区逐项审计并分批闭环（推荐）**：保留现有导航和业务服务，先建立共用验收契约，再按市场及公共能力逐批增强；只有真实数据和可执行操作成熟的能力才显示为可用。

选择方案 3。现有实现优先复用；只有缺少明确业务接口时才增加小型模块或接口，不做全站重写。

### 每个工作区的统一契约

1. `market`、`workspace`、`instrumentRef` 与当前选中上下文一致；不适用于标的的工作区不伪造标的依赖。
2. 每个数据块明确给出来源、来源时间/更新时间、状态、原因和可用证据引用。状态至少区分实时、延迟、缓存、部分成功、历史、暂无记录、来源不可用、当前市场不支持和请求失败。
3. “来源成功但没有记录”与“来源失败”分开显示；数据过期时明确标旧，不将缓存描述为实时。
4. 当前工作区只显示职责相关内容。市场切换、标的切换或工作区切换时，旧请求取消或丢弃，迟到响应不得覆盖当前视图。
5. 内容可操作时提供相应下一步（例如原文/证据、K 线定位、研究、提醒或复盘）；不能操作时解释原因，不放置失效按钮或空入口。

共用响应优先沿用已有数据封装和 API。需新建接口时仍使用同一市场上下文和数据状态语义，并执行服务端权限及标的身份校验。

## 分批交付

### 批次 1：工作区审计、边界与数据状态

- 建立 30 个工作区的能力清单：页面组件、接口、Provider、数据新鲜度、权限、现有操作、已知空缺和自动化覆盖。
- 修正导航注册表与页面内容/接口能力不一致、公共内容泄漏到专属工作区、旧请求污染当前上下文等问题。
- 补充“暂无记录、不可用、不支持、失败、缓存/过期”的一致呈现；不新增缺乏数据接线的占位卡片。

### 批次 2：股票工作区

- 逐项核对行情/选股、宽度、新闻事件、内部人、机构/13F、分析师、基本面和空头数据的覆盖、身份映射、发布时间与原文证据。
- 优先完善现有数据可支持的变化比较、时间线与 K 线/研究/日记跳转；无法可靠映射或不具备历史时显示具体限制。
- 不把 13F 季报披露包装为实时持仓，不混用 Form 4 股票与期权交易。

### 批次 3：期权工作区

- 围绕真实合约身份改善链筛选、报价质量、价差、快照历史对照、波动率和 Greeks 情景。
- 同一合约、来源和口径才比较；历史覆盖不足不展示分位、历史收益或伪曲线。
- 成本和到期损益依赖真实合约乘数、到期与可用报价；不满足条件时禁用并说明原因。

### 批次 4：虚拟币工作区

- 按交易所和产品身份接通现有行情/K 线、资金费率、OI、合约及盘口/资金流能力。
- 历史变化只比较同交易所、同合约类型、同单位口径；实时、轮询快照和历史归档分别标识。
- 数据源不覆盖链上/流量指标时明确不可用，不由行情或其他市场数据代填。

### 批次 5：预测市场工作区

- 展示平台、事件/市场 ID、YES/NO 身份、规则与截止时间、来源报价时间及流动性条件。
- 区分结果公布、平台结算、争议、来源未确认和追踪失败；官方结算证据可跳转，重复或修订状态可追溯。
- 校准与历史统计只在存在真实、可复核的历史概率和结算样本时提供，并展示样本量。

### 批次 6：共用研究、组合与操作工作区

- 打通筛选比较、标的分析、回测、风险、可信决策、研究实验、自选行动、自选和模拟持仓的上下文与证据引用。
- 保持实验/组合/日记/任务和模拟订单的权限边界；缺失基准、汇率、费用或历史价格时不补零。
- 展示策略版本、数据快照、样本区间和成本假设；无明确血缘的旧记录继续标记“未关联”。

### 批次 7：界面、性能与全矩阵验收

- 保持 B 版布局、三个主题和当前导航；统一控件与状态细节，不改变默认首页习惯。
- 手机端按单列/抽屉布局验证触控和返回状态；只加载当前工作区所需资源与请求。
- 按四市场及其适用工作区做完整能力矩阵抽检，验证功能区边界、选择标的后的内容/原因、访客权限和三个主题；不要求不适用的工作区出现在其他市场。

每批均先新增会失败的测试，再实现并运行相关测试、构建、Web/认证/浏览器冒烟、安全扫描和 `git diff --check`。失败批次不得进入部署。

## 数据、权限与安全边界

- 只使用现有免费/已配置来源；不因扩展范围而新增付费服务、抓取未授权内容或无界请求。
- Provider 只在同一市场和相同数据语义内降级。期权、虚拟币产品和预测合约都必须校验完整标的身份。
- 访客只读可公开摘要；私人自选详情、日记、组合、任务及模拟订单仍受管理员权限控制。
- 不连接券商，不启用真实下单；研究信号/AI 文本不得直接创建真实订单或绕过模拟账户风控。
- 数据源失败、零记录、缓存和不支持均保留原始原因，不以推测数据填充。
- 全程不使用子 agent，数据库、数据湖和工作区外用户文件原样保留。

## 验收标准

- 30 个工作区均有清晰职责、正确市场范围及真实数据/明确空状态；没有与当前区域无关的内容。
- 切换市场和标的后不出现跨市场标的、旧响应污染或不匹配的数据来源。
- 每个实际数据展示具有可核验来源、时间、状态和原因；事件有发布日期/时间及安全原文链接（若来源提供）。
- 历史/比较/研究仅使用身份、来源和口径匹配的数据，不读取未来信息、不插值、不默认零值。
- 图表、证据、列表和研究跳转保留同一市场、标的与时间上下文。
- 三个主题、桌面与手机布局可用；访客无法读取私人数据；真实交易执行器保持禁用。
- 发布前通过 `npm test`、`npm run build`、`npm run smoke:web`、`npm run smoke:auth`、`npm run smoke:browser`、`npm run security:scan` 和 `git diff --check`；需要生产发布时先备份、核对构建 Hash、健康状态与正式域名，并保留回滚目录。

## 执行边界

本规格确认全量范围和验收方式，不意味着所有工作区可在单次改动中安全完成。后续实现按上述批次推进；每批产出可验证结果，全部验收通过后再按项目既定流程推送和部署。当前阶段只提交本规格，不修改业务代码、数据库、数据湖、部署产物或 Telegram/跑单运行状态。
