# 导航稳定性与图表延迟挂载

本批实现已通过完整单测。整页冷加载改善至少20%的目标仍未达到，不把脚本缩小或单次更快的样本当作达标。沿用此前“发布已验收功能，性能目标继续保留”的授权。

## 本批变化

- 首屏不再默认激活总体页后再切换股票深链，避免无关内容短暂出现；默认首页仍由原有上下文恢复逻辑进入市场驾驶舱。
- 导航使用按宿主节点保存的相同标记缓存，重复渲染保留按钮节点和键盘焦点；市场、选中工作区、管理员/访客身份变化时仍更新。
- 工作区显隐只在状态变化时写入，移除一次重复的工作区可见性遍历。不改变四市场与功能区归属规则。
- 股票图表保留原始HTML和内联入口，在图表运行时就绪后才挂载；等待或资源失败时显示原因及重试。迟到的图表加载事件不能在其他工作区挂载股票图表。
- 形态开关、策略标记/列表/生命周期控件、虚拟币历史分页移入现有图表包；股票财务图形、来源时效说明、总体卡片/摘要、显示偏好和预测规则检查移入各自现有工作区包。共享状态和接口不另建副本。
- 测速增加浏览器运行错误断言，防止空白或损坏页面被判定为快速完成。

## 性能证据与未达标项

使用保留的原始基线 `f887c8b` 与本批构建，使用同一测速脚本、Chromium、CPU4倍节流、80ms/750Kbps网络；桌面1440×900、手机390×844。隔离账户和数据目录，关闭Telegram与AI执行，不复制生产数据库。构建与完整测试不和测速并行。

先新后旧，再反转执行顺序；每轮每种视口各3组冷/热加载。合并后每格6次，偶数样本中位数取中间两项平均，不丢弃较慢样本。
