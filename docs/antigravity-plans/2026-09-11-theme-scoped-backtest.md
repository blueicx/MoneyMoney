# MoneyMoney 主题统一与多市场独立回测执行计划

状态：已获批准，Codex 接手执行并完成本地验证

## 目标

采用方案 A：回测入口紧贴当前市场工作区。股票、期权、虚拟币各自使用对应市场的真实历史数据、字段、策略和结果；数据源不可用时明确展示状态，禁止使用其他市场或预测市场数据替代。

## 工作范围

### 1. 主题统一与状态表达

- 为行情筛选结果、标的卡片、表单控件、按钮、空状态、错误状态、加载骨架建立语义化 class。
- 统一使用现有主题变量，消除浏览器默认白底输入框、白色结果卡片和黑色默认文本。
- 正常、部分可用、暂不可用、降级数据分别显示来源、时间和原因；降级状态不能伪装成实时数据。
- 保留当前深色金色视觉体系，并验证不同主题变量下文字、边框和禁用态的对比度。

### 2. 多市场回测数据契约

- 将回测请求和响应统一绑定 `scope`、`instrumentId`、`dataSource`、`availability` 和 `asOf`。
- 服务端校验标的类型与 scope 一致；股票、期权、虚拟币、预测市场的请求和结果不得互相复用。
- 将当前预测市场专用的提示逻辑改为按 scope 分派；预测市场仍保留原有回测能力。
- 对没有真实历史数据的市场返回结构化不可用结果，包含缺失能力和建议动作，不返回伪造收益曲线。

### 3. 三类市场独立回测

- 股票：使用真实 OHLCV 历史数据，支持基础动量/均线类策略、指数或标的基准、手续费和滑点，结果标明数据源与区间。
- 期权：使用真实历史期权链、到期日、隐含波动率和 Greeks；若历史链数据源尚未覆盖，则显示期权历史数据不可用，不回退到股票或预测市场。
- 虚拟币：使用真实交易所 K 线，按 24/7 日历处理手续费；资金费率、未平仓量等字段只有在真实来源可用时才进入策略。
- 三个引擎共享回测结果格式和风险校验，但不共享市场专有字段与计算假设。

### 4. 前端工作区与加载性能

- 股票、期权、虚拟币页面只请求当前 scope 的行情、雷达、分析、风险和回测数据。
- 回测面板根据当前 scope 渲染对应参数；切换市场时清理上一市场结果，避免视觉和状态残留。
- 行情、市场专属雷达和回测元数据并行加载；结果区域采用主题化 skeleton。
- 缓存键至少包含 scope、instrumentId、周期和策略参数；短 TTL 数据允许 stale-while-revalidate，避免重复请求。
- 失败请求不得阻塞整页，单个市场组件独立显示不可用原因。

## 执行顺序

1. 盘点现有回测接口、数据源能力和前端生成 HTML，先补失败测试。
2. 建立统一回测契约和 scope 校验，保留预测市场兼容行为。
3. 接入股票与虚拟币真实历史数据回测；期权接入真实历史链能力，能力缺失时实现明确不可用状态。
4. 改造前端回测面板和结果渲染，接入主题 class 与市场切换清理。
5. 加入并行加载、作用域缓存和独立错误边界。
6. 运行完整测试、构建、Web smoke、主题视觉检查和跨市场隔离验收。

## 验收标准

- 切换股票、期权、虚拟币后，行情栏、雷达、分析、风险和回测只出现当前市场内容。
- 股票回测不会出现 funding rate；虚拟币回测不会出现 SEC/股票财报字段；期权回测不会被股票 OHLCV 冒充。
- 任何历史数据缺失均显示明确的来源、缺失原因和时间，不显示伪造结果。
- 筛选器、结果卡片、加载骨架、错误提示和禁用控件全部融入当前主题，不出现浏览器默认白色控件。
- 现有预测市场回测行为不回归。
- `npm test`、`npm run build`、`npm run smoke:web`、`npm run security:scan` 全部通过后，才允许提交、推送和部署。
