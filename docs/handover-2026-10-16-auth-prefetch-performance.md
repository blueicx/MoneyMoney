# 首屏鉴权等待与性能收尾

## 改动与边界

保留现有鉴权模块、执行顺序、工作区与图表接口，只在构建后的首页增加对原有 `/api/auth/status` 的 credentialed fetch preload。浏览器可在下载静态资源时发起状态请求，随后由现有鉴权模块消费同一响应。没有提前读取自选、账户、日记、订单等私人业务接口，也没有缓存私人 API 或持久化鉴权响应。

先增加缺少 preload 的失败测试，再实现。测试检查唯一 fetch preload、端点及 `crossorigin="use-credentials"`。测速额外断言每次导航只有一次鉴权状态请求，防止把重复请求当作提速。原有市场上下文、权限与 CSRF 处理不变。

试验过暂缓整页布局，虽然局部热加载较快，手机冷加载却没有稳定改善，已完整撤回对应代码和试验测试。保留日志 `mm-layout-gate-mobile.log`、`mm-layout-gate-before-mobile.log`、`mm-auth-preload-mobile.log`；这些不是最终验收数据。最终没有引入加载遮罩、隐藏页面或新的主题样式。
