# 专业研究闭环：优化方案与分批实施

## 边界与优化

沿用现有 SQLite、DuckDB/Parquet、模拟账本和四市场上下文，不另建账户，不自动修改正在运行的 AI 跑单。真实执行器保持关闭；实盘 CLOB、自动跨所对冲不纳入本次授权。套利雷达必须考虑身份、结算规则、手续费、资金费、深度及成交不同步，不使用“无风险”描述。实时推送有延迟、重连和降级状态，不承诺零延迟。提前决议监控只能称官方结果证据提醒，不能把新闻或初步结果当成最终结算。

AI 投委会采用串行 Bull / Bear / Risk 结构化角色，属于同一服务的三次有预算调用，不启用 Codex 子 agent；证据 ID 服务端校验，风控规则不由模型修改。财报检索先使用本地 SQLite FTS5/BM25，不引入额外模型或向量服务，引用真实段落及 SEC 原文；HTML 无稳定页码时不生成页码。只索引可合法获取的官方公开文件，不采集付费电话会议全文。

## 批次与交付门槛

### A：尾部风险、原文检索与部署基础

- `src/features/portfolio-tail-risk.ts`：同市场、同币种、完成日期对齐的历史 VaR / ES、样本协方差、最近 60 日及上一 60 日窗口比较。输入缺失、不同币种、期权/预测市场没有线性历史时返回明确不可用，不使用数组位置配对。当前权重历史风险不冒充实际账户收益。
- 接入既有 `/api/portfolio/analytics?history=1` 与组合工作区，不额外加载首屏数据。显示样本、尾部样本、币种、区间、计算口径及警告。
- `src/storage/financial-text-index.ts`：SQLite FTS5 官方财报段落索引、内容 Hash、发布时间/抓取时间、市场及标的过滤。相同文件幂等索引，`asOf` 排除晚发布文件，旧版本不覆盖其他标的。
- `src/web/financial-research-routes.ts`：仅管理员可手动索引当前股票的 SEC 10-K/10-Q，SEC 目录核验 CIK/申报编号；拒绝任意 URL、任意 SQL和任意代码执行。检索返回原文引用，不自动生成订单。
- 通知新增 Discord / 飞书 / 通用 HTTPS JSON Webhook，复用现有发送入口、并行隔离失败；默认未配置即关闭，禁止内网地址、重定向、秘密日志和任意用户提交地址。
- Docker 多阶段构建、非 root 运行、持久化数据卷、健康检查、无默认凭据；compose 仅绑定 loopback，不改现有 VPS 部署方式。

### B：策略与 AI 证据闭环

预测概率策略、资金费等真实成本项与事件回测分别在现有引擎增加版本化策略和数据要求；缺少历史或成交规则就阻止运行。加入有预算的三角色审议、反证和证据一致性校验。仅产研究建议和受现有门控约束的模拟意图，不启用实盘。

### C：实时数据与结果证据

仅订阅当前标的/监控列表，按场所隔离 SSE 通道；共享上游连接、预算、心跳、重连、熔断、轮询降级和更新时间。官方结果证据归档后才能通知，区分初步结果、确认结果、市场结算与争议。

### D：图表、筛选与布局

先用适配接口对照现有 Canvas 和 Lightweight Charts；验证许可、指标/绘图能力及移动交互后渐进迁移，不移除 Replay、证据和日期定位。布局仅允许当前工作区内卡片排序/隐藏，不恢复跨功能卡片污染。筛选预设使用对应市场字段与可靠证据，不跨市场混用 PCR 和资金费。

### E：模块拆分与性能

按本批涉及职责逐步拆分路由和工作区，不一次重写 React/Vite。保持 DOM/深链、三个主题、管理员/访客权限与行情空状态。每批记录冷/热加载和上游预算，不以入口数量计完成。

## 测试、发布及证据

每个代码批次先写失败测试，再实现。完整运行测试、构建、Web/认证/浏览器冒烟、安全扫描与变更范围 diff 检查。生产发布需 GitHub 推送、dist 备份/原子切换、正式域名版本/Hash/健康核验，仅操作 moneymoney.service。实盘、通知真实投递、Docker 启动、浏览器矩阵各自独立验收，未执行不能标为已验证。已有数据库、数据湖和 scratch 原样保留。
